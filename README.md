# DWA C 版整机（10.20）

本仓库保存当前用于板端测试的 C 版单进程 DWA 工程。`10.20` 基于 `10.16-ok`，保留统一脱困、电机桥脱困 IMU 角速度补偿和传感器故障停车联锁，并修正持续脱困、手动转向被反向接管及侧向安全判定问题。板端目标机为 ARM64；测试前请确认传感器、控制器串口映射与实际硬件一致。

## 设备映射

- 左雷达：`/dev/ttyS4`
- 右雷达：`/dev/ttyS5`
- 电机控制器：`/dev/ttyS6`
- BMI270 IMU：`/dev/i2c-3`（当前板接线；不是 `/dev/i2c-4`）

程序入口中的串口默认值和 IMU 驱动中的 I²C 节点均按上述板端映射配置。更换硬件接线时，应同步检查 `c/apps/robot_main.c` 与 `c/src/drivers/bmi270.h`。

## 目录

- `c/`：规划、安全、感知、融合、电机桥、运行时、应用入口和回归测试；`c/src/drivers/` 中少量 C++ 文件仅用于调用雷达 SDK。
- `config/dwa_planner.yaml`：规划与安全参数。
- `config/lidar_filter.yaml`：双雷达滤波参数。
- `third_party/cspc_lidar_sdk_ros2/sdk/`：COIN-D6 雷达供应商 SDK。SDK 自带的 C++ 源码是雷达适配依赖，不是旧版 C++ DWA 规划器或电机桥。

旧的 C++ DWA 规划器、电机桥实现、ROS 启动链、旧对拍程序和历史分析文件不属于此版本。除雷达适配层和供应商 SDK 外，控制及规划主链路为 C 实现。

## 本版本主要行为

### 统一脱困

- DWA 硬停止和电机桥兜底保留各自的脱困触发条件，但触发请求交由统一脱困决策与输出路径处理，避免两路方向控制互相争抢。
- 脱困转向使用 IMU 实际角速度反馈进行有限幅补偿，并在结束、转向方向变化或 IMU 数据失效时清理补偿状态。
- 轮速反馈新鲜度按电机桥统一时钟基准判断，避免时间戳基准不一致造成误判。
- 脱困选向侧距按 `0.315 m` 半宽计算（对应 63 cm 总宽）；这只用于脱困安全选向，不会改变 DWA 车体碰撞包络。当前 `footprint_half_width` 仍为 `0.27 m`（54 cm 总宽）。
- 手柄有明确左右转意图时立即取消脱困并交回 DWA；选定侧变得不安全或无法确认时停止并锁止，不反向改选另一侧。两侧都未知时不擅自选择方向。
- 单次脱困最长 2 秒；遇到手动接管、侧向不安全或超时后，必须先清除触发条件才允许重新评估，避免反复重入或持续单向转动。

### 传感器故障停车

- 左、右雷达分别检查数据新鲜度；融合数据不能用一侧的新扫描掩盖另一侧过期。
- 整机入口启用电机桥传感器联锁：任一侧雷达超时，或 IMU 连续 1 秒没有有效采样（包括启动后一直没有有效采样），电机桥强制输出中立；传感器恢复新鲜后才解除联锁。雷达超时沿用 `dwa_planner.yaml` 中的 `scan_timeout_sec`。
- 状态字故障位定义：bit0（`0x01`）左雷达、bit1（`0x02`）右雷达、bit2（`0x04`）IMU；整机入口配置为协议 `2.3`，主机软件会将对应状态编码到协议帧并记录故障原因。其他不含状态字的协议不会发送这些故障位。
- **控制器显示/识别限制：**控制器 MCU 固件不在本仓库，尚不能保证它会解释或显示新增 IMU 状态位。另有既存的控制器反馈在线门控：若连续 1 秒收不到有效控制器反馈，软件会暂停发送，因此反馈离线期间无法继续向 MCU 发送传感器故障状态。

### 避障与脚尖碰撞保护

- 碰撞前缘采用脚尖前缘 `toe_front = 0.90 m`。
- 前向安全候选参与净距与硬停止判断，避免贴近脚踏区域的障碍被通用自车过滤整体剔除。
- 脚尖纵向碰撞余量为 `toe_collision_margin_m = 0.10 m`；不扩大侧向碰撞宽度，避免通道弯道墙的侧向包络整体提前。

## 构建与测试

### Linux 宿主机回归测试

```bash
cmake -S c -B build-c \
  -DDWA_C_ENABLE_HOST_TOOLS=ON \
  -DCMAKE_C_STANDARD_LIBRARIES=-lm \
  -DCMAKE_CXX_STANDARD_LIBRARIES=-lm
cmake --build build-c
ctest --test-dir build-c --output-on-failure
```

Linux GCC 链接数学库需要上述 `-lm` 配置。Windows/MinGW 构建时可省略这两个标准库参数。

### ARM64 板端交叉编译

```bash
cmake -S c -B build-aarch64 \
  -DCMAKE_TOOLCHAIN_FILE=c/cmake/aarch64.cmake \
  -DDWA_C_ENABLE_HOST_TOOLS=OFF
cmake --build build-aarch64
```

主要产物包括：`robot_main`（整机单进程入口）、`dwa_main`（规划/回放入口）和 `bridge_main`（C 版电机桥入口）。仓库只跟踪源码、配置和测试，不提交本地构建目录或板端二进制。

## 板端启动与安全

部署 `robot_main` 到板端 `bin/robot_main`，并将 `config/` 下配置文件放到对应位置。仓库内 C 版启动脚本：

```bash
./c/apps/run_robot.sh
```

接电机和雷达进行实车测试前，确认串口未被其他进程占用，并准备可立即使用的物理急停。传感器故障联锁是额外的软件保护，不能替代硬件急停；必须在有人监管且可立即断电的条件下测试。
